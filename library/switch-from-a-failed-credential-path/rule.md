# Stop repeating a failed credential path and offer the user’s requested alternative

When a user asks for a simpler supported way to complete a task after a method repeatedly fails, switch to that method and give concrete steps. Do not ask them to repeat a failed action without new evidence that the next attempt addresses the failure.

## How to check

After each failed attempt, check whether the next instruction changes the cause of failure; if not, offer a viable alternative instead of another retry.
